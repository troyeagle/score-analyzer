## 一、问题排查结果

### 1.1 小节统计错误

**问题**: 原系统显示 714 个小节，实际应为 102 小节 × 7 个声部。

**原因**: `MusicXMLParser` 将所有声部的小节扁平化存储到一个数组中，导致 7 × 102 = 714。

**修复**: 重构数据模型，按声部层次组织小节。

### 1.2 多谱表未支持

**问题**: P7 (Piano) 有 2 个谱表（左右手），但原系统无法区分。

**修复**: 
- 解析 `<staves>` 元素获取谱表数量
- 解析 `<clef number="N">` 为每个谱表指定谱号
- 使用 `<staff>N</staff>` 将音符分配到对应谱表

### 1.3 多声部未支持

**问题**: P7 使用 voice 1, 3, 4 以及 `<backup>` 元素，原系统无法正确处理。

**修复**: 
- 解析 `<voice>` 元素标识声部编号
- 按 voice 分组存储音符
- `<backup>` 元素用于时间点回退，不影响数据结构

### 1.4 歌词解析缺失

**问题**: XML 包含大量歌词数据（日语、罗马字、英语），但原系统完全跳过。

**修复**: 添加 `<lyric>` 元素解析，支持多行歌词和音节拼接。

## 二、重构内容

### 2.1 数据模型重构

**新数据结构**:
```
MusicXMLParseResult
├── metadata
└── parts[]
    ├── id, name, staves
    ├── measures[]
    │   ├── attributes
    │   └── voices (Map<number, Voice>)
    │       └── notes[]
    └── transpose
```

**关键变化**:
- `Part` 包含完整的 `measures` 数组
- `Measure` 使用 `voices` Map 组织多声部
- `Voice` 包含 `staff` 属性区分谱表
- `Note` 增加 `voice`, `staff`, `isChord`, `isRest`, `lyrics`, `tie` 等字段

### 2.2 MusicXMLParser 重构

**新增解析功能**:
- 多谱表解析 (`staves`, `clef`)
- 多声部解析 (`voice`, `backup`)
- 歌词解析 (`lyric`)
- 连音线解析 (`tie`)
- 速度标记解析 (`metronome`)
- 调号变化支持
- 和弦音符识别

### 2.3 VexFlowRenderer 重构

**新增渲染功能**:
- 大谱表渲染（钢琴左右手）
- 花括号连接
- 多声部独立渲染
- 声部选择性显示

### 2.4 ScoreView 更新

**新增界面功能**:
- 声部选择器（全选/取消）
- 声部信息显示（名称、小节数、是否大谱表）
- 谱表间距调节

## 五、经验总结

1. **数据模型设计**: 保持层次结构，不要扁平化存储
2. **MusicXML 复杂性**: 需要处理大量可选元素和特殊情况
3. **Sibelius 兼容性**: 注意 Sibelius 导出的特殊标记（color, 空 attributes 等）
4. **测试驱动**: 使用真实文件作为测试数据，确保解析正确性
5. **多声部处理**: voice 和 backup 是 MusicXML 中最复杂的部分
