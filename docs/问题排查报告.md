**排查日期**: 2026-05-14

## 一、核心问题概述

### 1.1 小节统计错误

**问题描述**: 当前系统显示 714 个小节，实际应为 102 个小节 × 7 个声部。

**根本原因**: `MusicXMLParser.extractMeasures()` 方法将所有声部的小节都添加到一个扁平的 `measures` 数组中，没有按声部分组。

```typescript
// 当前错误实现
const measures: Measure[] = []
partElements.forEach((partElement) => {
  // 每个声部的小节都被添加到同一个数组
  measures.push(...)
})
// 结果：7 × 102 = 714 个小节
```

**正确实现**: 应该按声部组织小节，或者在小节数据中保留声部信息。

---

### 1.2 多谱表（Staves）未支持

**问题描述**: P7 (Piano) 有 2 个谱表（高音谱表和低音谱表），但当前代码没有解析 `<staves>` 元素。

**XML 结构**:
```xml
<part id="P7">
  <measure number="1">
    <attributes>
      <staves>2</staves>
      <clef number="1"><sign>G</sign><line>2</line></clef>
      <clef number="2"><sign>F</sign><line>4</line></clef>
    </attributes>
    <note>
      <staff>1</staff>  <!-- 高音谱表 -->
      <voice>1</voice>
    </note>
    <note>
      <staff>2</staff>  <!-- 低音谱表 -->
      <voice>3</voice>
    </note>
  </measure>
</part>
```

**影响**: 
- 无法区分钢琴的左右手
- 无法正确渲染大谱表

---

### 1.3 多声部（Voice）和 Backup 未支持

**问题描述**: P7 使用 voice 1, 3, 4，以及 `<backup>` 元素在同一小节内实现多声部。

**XML 结构**:
```xml
<measure number="1">
  <!-- voice 1: 右手高音 -->
  <note><voice>1</voice><staff>1</staff></note>
  <note><voice>1</voice><staff>1</staff></note>
  
  <!-- 回退到小节开始 -->
  <backup><duration>1024</duration></backup>
  
  <!-- voice 3: 左手 -->
  <note><voice>3</voice><staff>2</staff></note>
  <note><voice>3</voice><staff>2</staff></note>
</measure>
```

**影响**:
- 多声部音符会重叠显示
- 左手声部可能被忽略或错误解析

---

### 1.4 Note 类型缺少关键字段

**问题描述**: 当前 `Note` 接口缺少 `voice`、`staff`、`chord`、`lyrics`、`tie` 等字段。

**当前定义**:
```typescript
interface Note {
  id: string
  pitch: string
  duration: number
  type: string
  stem: string
  beam?: string
  accidental?: string
  dots?: number
}
```

**需要添加**:
```typescript
interface Note {
  // ... 现有字段
  voice: number        // 声部编号 (1, 3, 4)
  staff: number        // 谱表编号 (1, 2)
  isChord: boolean     // 是否为和弦音符
  tie?: 'start' | 'stop' | 'continue'
  lyrics?: Lyric[]     // 歌词
  isRest: boolean      // 是否为休止符
}
```

### 1.5 调号解析不完整

**问题描述**: 文件中存在调号变化（measure 18: E major → D major），但当前代码只解析第一个调号。

**XML 结构**:
```xml
<!-- measure 18 -->
<attributes>
  <key>
    <fifths>2</fifths>
    <mode>major</mode>
  </key>
</attributes>
```

**影响**: 调号变化后，后续小节的调号显示不正确。

---

### 1.6 速度（Tempo）解析未实现

**问题描述**: 当前代码查找 `direction[tempo]`，但实际 XML 中速度标记在 `<metronome>` 元素内。

**XML 结构**:
```xml
<direction>
  <direction-type>
    <metronome>
      <beat-unit>quarter</beat-unit>
      <per-minute>144</per-minute>
    </metronome>
  </direction-type>
</direction>
```

**当前代码**:
```typescript
// 错误：查找 direction[tempo] 属性
const direction = this.doc.querySelector('direction[tempo]')
```

---

### 1.7 歌词解析未实现

**问题描述**: XML 中包含大量歌词数据（日语、罗马字、英语），但当前代码完全跳过了歌词解析。

**XML 结构**:
```xml
<note>
  <lyric number="part1verse1">
    <syllabic>single</syllabic>
    <text>君</text>
  </lyric>
  <lyric number="part1verse2">
    <syllabic>single</syllabic>
    <text>ki</text>
  </lyric>
</note>
```

## 二、架构问题分析

### 2.1 数据模型设计缺陷

**问题**: 当前数据模型是扁平化的，没有体现乐谱的层次结构。

**当前结构**:
```
MusicXMLParseResult
├── metadata
├── parts[]          // 声部列表
├── measures[]       // 所有小节（扁平）
├── notes[]          // 所有音符（扁平）
└── annotations[]    // 所有标注
```

**问题**: 
- measures 和 notes 是扁平数组，丢失了声部归属信息
- 无法区分哪个小节属于哪个声部
- 无法区分哪个音符属于哪个谱表/声部

### 2.2 渲染引擎设计缺陷

**问题**: 当前渲染引擎假设所有声部共享相同的布局。

**正确设计**: 每个声部应该有独立的布局，P7 (Piano) 需要大谱表布局。

---

## 三、解决方案

### 3.1 数据模型重构

```typescript
// 新的数据模型
interface MusicXMLParseResult {
  metadata: ScoreMetadata
  parts: Part[]        // 声部列表（包含完整结构）
}

interface Part {
  id: string
  name: string
  abbreviation: string
  staves: number       // 谱表数量
  measures: Measure[]  // 该声部的小节
}

interface Measure {
  id: string
  number: number
  attributes: MeasureAttributes
  voices: Voice[]      // 按声部组织
}

interface Voice {
  id: number           // voice 编号
  staff: number        // 谱表编号
  notes: Note[]
}
```

### 3.2 多谱表支持

- 解析 `<staves>` 元素获取谱表数量
- 解析 `<clef number="N">` 获取每个谱表的谱号
- 解析 `<staff>N</staff>` 将音符分配到对应谱表

### 3.3 多声部支持

- 解析 `<voice>` 元素获取声部编号
- 解析 `<backup>` 元素处理声部回退
- 按 voice 分组音符
